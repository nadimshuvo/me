Software engineering

Everything worth learning.

The JavaScript stack that ships a product, and the computer science under it. The machine, the algorithms, and the systems a software engineer is expected to know.

The order

Eight steps. One stack.

Learn these in sequence. A framework on top of a shaky language does not hold.

  1. HTML, CSS, JavaScript The document, the layout, and the language.
  2. Git and the terminal History, branches, and how a project actually runs.
  3. React Components and state. Interfaces you can change.
  4. Node.js and REST A server, an API, and JSON a client can trust.
  5. SQL Tables, relations, and a database you can query.
  6. TypeScript Types on the same language, client and server.
  7. Next.js Routing, rendering, and data closer to the server.
  8. Auth, then deploy Closed routes, a real host, and one product end to end.

The set

Languages, frameworks, tools.

What sits inside those eight steps. Learn the name, then the job it does.

10

APIs that last

A URL other people's code will call for years. Design it like a contract.

OpenAPI

The contract written down, so the client and the server cannot drift quietly.

Status and errors

The right status code, and an error body a client can branch on.

Pagination

Never return the whole table. A page, a cursor, and a way to ask for the next.

Idempotency

Sending the same request twice must not charge, create, or email twice.

Rate limits

How many calls, in what window, and what the client should do when told to wait.

Webhooks

You call them when something happens. They do not sit and poll you.

gRPC

A typed call between services, when JSON over HTTP is too loose.

Versioning an API

Add fields. Do not rename the ones already in production.

11

Data you keep

Normalization

One fact, stored once. Duplication is a bug that arrives later.

Migrations

Change the schema in a step you can run again, and roll back.

Window functions

Ranks, running totals, and the row beside this one, in SQL.

Backups

A copy you have restored at least once. An untested backup is a hope.

SQLite and Postgres

A file is enough for some products. A server is enough for most of the rest.

Search

When LIKE is no longer the feature. An index built for finding text.

12

Releasing it

Feature flags

Ship the code dark. Turn the behavior on for a few people first.

Canary

A small slice of traffic on the new version. Watch it, then continue.

Rollback

The previous version, ready. Practice it before you need it.

Secrets

Keys live outside the repository. The repo is not a vault.

Supply chain

The packages you install are code you run. Know where they came from.

Serverless

A function that runs when called, and nothing when it does not.

Monolith or services

One deployable, until the team is large enough that the split pays for itself.

Licenses

What you may use, and what you may ship. Read the license before the import.

How a page gets fast

Speed is a set of measurements. Learn the names, then look at a real trace.

Rendering

HTML, CSS, and JavaScript, and the order the browser turns them into pixels.

Web Vitals

Loading, interactivity, and layout shift. The numbers users feel.

Where it renders

On the server, in the browser, or both. Hydration is the handoff.

Cache headers

What may be stored, for how long, and who is allowed to store it.

A CDN

A copy of the static file, closer to the person asking for it.

The bundle

How much JavaScript ships. Split it, and load the rest later.

Data on the client

Cache the response, show the last one while the next one loads, and avoid a second identical request.

Measuring

Lighthouse and a trace. A feeling that it is slow is the start, not the evidence.

14

Who is calling

Identity is a protocol. Learn the handshake before you store a password.

Sessions

A cookie that points at a record on the server. The server can forget it.

Tokens

A signed claim the client carries. Short-lived, and checked on every call.

OAuth and OIDC

Let another service prove who the person is. You still own the session after that.

Passwords

A slow hash, a salt, and nowhere near a log line. You store the hash.

Cookies

HttpOnly, Secure, SameSite. The flags are the security model.

CORS

Which other origins may call this API from a browser, and with which headers.

Least privilege

A key, a role, and the smallest set of actions that role may take.

15

When a call fails

Networks drop packets. Databases lock rows. Design for the retry.

Timeouts

Every outbound call has a deadline. Waiting forever is a bug.

Retries

Try again, with backoff and jitter, and only when the operation can be repeated.

Consistency

Read-your-writes, or a replica that is a few seconds behind. Pick one on purpose.

Isolation

What one transaction is allowed to see of another that has not committed.

N+1 queries

One query for the list, then one per row. The page looks fine until the list grows.

Sagas

A business action split across services, with a way to undo the steps that succeeded.

Load tests

Hit it harder than production, on purpose, before production does.

SLOs and on-call

A target for how often it may fail, a runbook, and a person who will read the page.

16

More than one thing at once

The browser is one thread. The server is many. Both can still race.

The event loop

One thread, a queue of tasks, and the moment your function gets to run.

Promises

A value that arrives later. Await it, or the next line runs too soon.

Threads

Two stacks of execution, sharing memory. Fast, and easy to corrupt.

Locks

One writer at a time. A lock you forget to release is a deadlock.

Races

The result depends on which one finishes first. That is a bug with a clock.

Backpressure

The producer is faster than the consumer. Slow the producer down.

Cancellation

The user left. The request should stop, including the work it already started.

Shared nothing

Pass messages instead of sharing memory. Go and Rust push you this way.

17

Security as a practice

A checklist you run on every change, not a chapter you read once.

Threat modeling

What are we protecting, from whom, and which path gets them there.

Authn and authz

Who they are, and what that identity is allowed to do. Two different checks.

TLS

The handshake, the certificate, and why a padlock is not the whole story.

Injection

SQL, shell, HTML, and any string that gets executed instead of stored.

Dependencies

A new version can be the attack. Review it, and let a bot watch the rest.

Secrets in logs

A token in a stack trace is a token in someone else's laptop.

Authorization bugs

The request is valid, and it touches someone else's row. Check the owner.

Accessibility rules

WCAG. Keyboard, names, contrast. A broken page for some people is a broken page.

18

Data that grows

The schema that worked for a thousand rows is a different problem at a hundred million.

Indexes, specifically

B-trees, what they speed up, and the writes they slow down.

EXPLAIN

Ask the database how it will run the query before you guess.

Replication

A primary that takes writes, and replicas that serve reads a moment later.

Sharding

Split the rows across machines. The split key is the decision you live with.

CAP

During a partition you choose consistency or availability. You do not get a third option.

Cache-aside

Read from the cache, fill it on a miss, and delete it when the row changes.

Events as the record

Store what happened, and rebuild the current state from that log.

The domain

Name the things the business names. The tables should sound like the work.

19

The box and the record

Someone still logs into a machine. Someone still has to explain why the design is this one.

SSH

A key, not a password pasted into chat. The door onto the server.

Permissions

User, group, and mode. A process runs as someone. That someone should be small.

systemd

The process that starts your service, restarts it, and keeps its logs.

Logs as a stream

Write to stdout. Let the platform collect it. A file on the box disappears with the box.

Signals

Traces, metrics, and logs are three views of one failure. Keep the request id on all three.

History of the branch

Rebase, blame, and a history a reviewer can follow.

Decision records

A short note: the context, the choice, and the options you rejected.

Functions, composed

Small functions, data in and data out. A style you can use in any language.

20

How a program is built

Source is not what the machine runs. Something turns one into the other.

Lexing and parsing

Characters become tokens, tokens become a tree. Every language starts here.

Checking types

Some mistakes are found before the program runs. That pass has a name.

Linking

Separate compiled pieces, joined into one program the loader can start.

The build

One command that typechecks, bundles, and emits the artifact you will ship.

Packages

A versioned archive, a registry, and a lockfile that pins what you installed.

Images

A filesystem plus a start command. Layers, so the next build reuses the last.

Registries

Where the image lives after the build, and where production pulls it from.

The same install twice

A lockfile and a pinned base image. Tomorrow's build matches today's.

21

Tests that tell the truth

A green suite is only useful if a real bug would have turned it red.

Unit

One function, given inputs, checked outputs. Fast, and blind to the wiring.

Integration

The function, the database, and the queue, in one test. Slower, and closer to life.

End to end

A browser, a real click, a real server. Few of these. They guard the path a person takes.

Doubles

A stand-in for the network or the clock. Name what you replaced, or the test lies.

Test first

Write the failing check, then the code that turns it green, then clean the code.

Coverage

Which lines ran. A high number with weak assertions is still a weak suite.

Flakes

A test that fails on Tuesday and passes on Wednesday. Fix it, or delete it.

The debugger

Stop on a line, look at the values, step. Faster than printing your way there.

22

Under the process

The operating system is the program your program asks for everything.

System calls

The narrow door from your code into the kernel. Open, read, write, fork.

Virtual memory

Each process believes it owns the address space. The kernel is paging underneath.

Scheduling

Many processes, few cores. The kernel decides who runs in the next slice.

File systems

Names, inodes, and blocks. A path is a lookup, not the bytes themselves.

Pipes

One program's output is the next program's input. The shell is built on this.

HTTP/2 and HTTP/3

Many requests on one connection, then a protocol on UDP. The web moved.

The HTTP spec

Semantics, methods, and status codes, written down as the standard.

Partitions

A huge table split by a key, so one query does not scan every year of rows.

23

The line to production

A commit becomes an artifact, an artifact becomes a running process, on purpose.

Continuous delivery

The main branch is always releasable. The pipeline is what makes that true.

Trunk-based development

Short branches, merged daily. Long-lived branches hide the conflict until Friday.

Environments

Local, a shared staging copy, then production. Config changes. The artifact should not.

The workflow

Install, test, build, publish. Each step fails the run if it fails.

Artifacts

The zip, the image, the bundle. Built once, promoted, not rebuilt per environment.

Previews

A URL for the pull request, so a reviewer can click the change.

24

The numbers

Enough math to read a chart, a ranking, and a model without inventing a story.

Statistics

Means, variance, and a sample. Enough to read a latency chart honestly.

Probability

Distributions, and what "unlikely" actually costs you in production.

Linear algebra

Vectors and matrices. The math under graphics, ranking, and most machine learning.

25

Packets

HTTP sits on this. When the request never arrives, this is the layer you are debugging.

TCP

A handshake, ordered bytes, and a connection that notices when the other side vanishes.

UDP

A datagram, no handshake, no promise it arrives. Useful when late is worse than missing.

DNS records

A name maps to an address, a mail server, or another name. The record type is the meaning.

Subnets

A slice of addresses that share a prefix. Routing starts by asking which slice.

NAT

Many machines behind one public address. The router rewrites the packet on the way out.

Ports

The number that picks which process on the machine receives the packet.

26

The shape of the code

Two designs can both pass the tests. One of them will still hurt to change.

Coupling

How much one module must know about another. Less is easier to move.

Cohesion

The things in one module belong together. A grab bag is a module that grew by accident.

State machines

A finite list of states, and the events that move between them. Illegal combinations disappear.

Errors as values

The failure comes back beside the result. Callers have to look at it.

Data that stays put

Build the next value. Leave the previous one alone. Easier to reason about, and to share.

Names

The function's name is the comment. If the name needs a paragraph, the function is two functions.

27

What the browser keeps

Not every byte has to round-trip. Know where it lives, and who can read it.

localStorage

A few strings that survive a reload. Synchronous, small, and visible to any script on the origin.

IndexedDB

A real database in the browser. For data too big, or too structured, for a string.

The Cache API

Store responses. A service worker can answer from here when the network is gone.

Service workers

A script that sits between the page and the network. Offline, and push, live here.

What belongs there

Preferences and caches. Tokens and passwords belong in a cookie the page's JavaScript cannot read.

28

Algorithms you will name

The ones that show up in interviews, and in the profiler when a loop goes quadratic.

Breadth-first search

Layer by layer. The shortest path when every edge costs the same.

Depth-first search

Follow one branch to the end, then back up. Cycles, components, and orderings.

Shortest paths

Dijkstra, when edges have different costs. A priority queue does the choosing.

Heaps

The smallest item is always at the top. Scheduling, and that priority queue.

Greedy

Take the best local step. Correct only when the problem promises that works.

Divide and conquer

Split, solve the halves, combine. Mergesort is the picture.

Disjoint sets

Which pieces are already connected. Union them in almost constant time.

Tries

A tree of prefixes. Autocomplete, and routing a string one character at a time.

29

What the chart is made of

An average hides the slow request. Learn the shapes people actually page on.

Percentiles

p50 is typical. p99 is the slow tail a few users feel on every visit.

Histograms

Buckets of latency. A histogram can answer a percentile later. An average cannot.

Traces

One request, many spans, across the services it touched. The waterfall of a single call.

Dashboards

A few charts you look at during an incident. A wall of charts is a folder nobody opens.

30

Agreement

More than one machine has to decide the same thing, while some of them are late or gone.

Consensus

A majority agrees on the next value. Raft is the version people actually implement.

Quorum

Enough copies to proceed. A minority can be down and the write still counts.

A leader

One node accepts writes. The others follow, and elect a replacement when it stops.

Clocks

Wall clocks disagree. A logical clock orders events without trusting the time of day.

Delivery

At least once means you will see duplicates. The consumer has to tolerate them.

Dead letters

A message that failed enough times goes somewhere a person can look, instead of looping forever.

The outbox

Write the row and the event in one transaction. Publish the event after the commit.

31

The browser's rules

The platform has opinions. Learn them before you fight a bug that is actually a rule.

The DOM

The tree the browser built from your HTML. JavaScript changes this tree, and the screen follows.

Events

A click starts at the target and walks the tree. Know which node is listening.

Specificity

Two rules want the same property. The cascade decides. Specificity is how.

The box

Content, padding, border, margin. Width means different things until you say which.

Same origin

A page may read responses from its own scheme, host, and port. Other origins need permission.

Content Security Policy

A header that says which scripts, styles, and frames this page is allowed to load.

32

Change it while it runs

Production has the old code and the new code in the same minute. The data has to survive both.

Expand, then contract

Add the new shape first. Move readers and writers. Remove the old shape last.

Two versions at once

The previous deploy is still serving. Your migration must be readable by that code.

Blue-green

Two full copies. Send traffic to the new one, and keep the old one warm until you are sure.

Config

Environment, flags, and secrets stay outside the artifact. The same build runs in every place.

Order

Migrate before the code that needs the column. Remove a column only after no code reads it.

33

A cloud

Someone else's data center, with your name on the bill and on the failure.

Regions and zones

A region is a geography. A zone is a data center inside it. One zone can fail alone.

A private network

Your subnets, your routes, and which of them may see the public internet.

Identity for machines

A role the service assumes. People get users. Programs get roles.

Object storage

Blobs with a key. Uploads, exports, and anything that is a file rather than a row.

Autoscaling

More copies when the metric rises, fewer when it falls. The metric has to mean load.

The bill

Egress, idle replicas, and a log line per request. Cost is a design constraint.

34

The day

The job is mostly other people's code, other people's words, and a ticket.

Reading code

Start at the entry point, follow one request, and write down what you still do not know.

Writing

A ticket, a review comment, a design note. Short, specific, and possible to act on.

What to look for

In a review: correctness, a clearer design, tests, and names. Style is last.

Experiments

Two versions, a metric decided in advance, and a sample large enough to mean something.

Alerting

Page a person for symptoms a user feels. A chart can wait until morning.

The shell, fluently

Pipes, find, and a loop. Enough to inspect a box without installing a new tool first.

35

Inside the database

Indexes and transactions are the features. This is the machinery under them.

The log

A change is written to the log before the page on disk changes. After a crash, recovery replays that log.

Versions

A reader sees a snapshot. A writer creates a new version of the row. Each proceeds on its own.

The tree

An index is a shallow tree of pages. That shape is why a lookup stays cheap as the table grows.

Pages

Disk is read in pages, and the hot ones stay in memory. A miss is a trip to disk.

A checkpoint

The log cannot grow without a bound. A checkpoint marks the place where the pages have caught up.

Vacuum

Old row versions stay until something removes them. Left alone, the table keeps the rows nobody can see.

36

Outside the request

Some of the job is mail, money, a file, and a clock.

Mail

Delivery is its own protocol. The receiver checks the sender with SPF, DKIM, and DMARC.

Money

Count the smallest unit as an integer. Charge with a key the client can safely send again.

A file upload

Decide the type, the size, and the bucket before you accept the bytes. The filename is only a label.

Privacy

Collect what the feature needs, know how long you keep it, and be able to delete one person.

Many tenants

Every query carries a tenant. A missing filter is another customer's rows.

A schedule

Some work starts because the clock said so. It still needs a timeout, a log, and a single run.

37

Shapes you will reach for

A few structures show up by name. Know the question each one answers, and the answer it can get wrong.

A bloom filter

A small structure that answers "is this here?" A no is certain. A yes can be a collision.

Consistent hashing

Keys sit on a ring. Add one node, and only the keys beside it move.

An LRU

The cache drops whatever has gone the longest without a use.

A token bucket

Requests spend tokens. A burst fits until the bucket is empty, and then the rate holds.

Topological sort

An order of tasks where every dependency comes first. A cycle means no such order exists.

HyperLogLog

A count of distinct items that fits in kilobytes, and is a little bit off.

38

The client of the database

The engine keeps the bytes. Your process still borrows a connection and lives among the other transactions.

A pool

A connection per request exhausts the database. A pool lends a few, and it has a maximum.

A prepared statement

The database parses the shape once. The values travel separately, so a quote in a name stays data.

A deadlock

Two transactions each hold the row the other wants. One is chosen to fail, and that one retries.

A long transaction

An open snapshot keeps old row versions alive. Finish the work, or give the statement a timeout.

Waiting for a connection

A full pool is a queue. Waiting for a free connection needs a deadline of its own.

The replica is behind

A read right after a write can miss the row, when the read went to a copy that has not caught up.

39

One kernel

A container is a process with its own view of the machine, and a ceiling. The kernel under it is the host's.

A namespace

Its own process list, network, and mounts. The other container's files are outside that view.

A cgroup

CPU and memory stop at a number you set. Past it, the process waits, or the kernel stops it.

Capabilities

Root inside still holds a list of privileges. Drop every one the process can live without.

A volume

The container's own files go with it. A volume is the directory that is still there afterward.

The process

You name one command. When that process exits, the container is finished.

A health check

A command that has to succeed on a timer. Failure is how the platform knows to replace it.

40

A log you can reread

A queue forgets a job when a worker finishes it. This log keeps the events, and each reader keeps a bookmark.

A partition

One ordered slice of the topic. The order holds inside the slice.

An offset

The number of the next event this reader wants. The log leaves the bookmark to the reader.

A consumer group

The partitions are split across the readers in the group. Each partition has one of them.

Retention

Events past an age or a size are deleted. A reader who was late finds a gap.

Compaction

For each key, the latest value stays. The earlier values for that key go.

Replay

A new reader starts at the oldest offset still kept. The producers send nothing a second time.

41

The plan

The database chooses how to run the query. Reading that choice is part of writing SQL.

A sequential scan

The database reads the table from one end to the other. Cheap on a small table, and the whole disk once the table has grown.

An index scan

It walks the tree, then fetches the rows those leaves point at.

Join order

Which table is read first changes how many rows the next step has to look at.

Statistics

The planner guesses from counts it stored earlier. A guess about distinct values steers the whole plan.

A stale statistic

After a big load, the stored counts still describe the old table. Refresh them, then look at the plan again.

The estimate

The plan prints the rows it expected beside the rows it actually touched. The gap is the clue.

42

The words

Search is its own index, built from the words inside the rows.

Tokens

The text is split into words. Case and punctuation come off.

An inverted index

For each word, the list of documents that contain it.

Stemming

Running and runs land on one stem, so a query for one still finds the other.

Ranking

A rare word in the query counts for more than a word that sits in every row.

43

The warehouse

The database that takes the order is a poor place to ask how the year went.

The report path

Orders are written one at a time. A report reads long ranges and sums them.

A warehouse

A separate store, shaped for those scans, and loaded from the one that takes the writes.

Load, then transform

Land the copy first. Shape it where people read, so a bad transform can be run again.

The grain

One row means one fact. An order line and an order are two grains, and mixing them double-counts.

Late rows

An event from Tuesday can arrive on Thursday. The Tuesday total has to be allowed to change.

A changing dimension

The customer's city changes. A report of that day still needs the city they had then.

44

When a cache misbehaves

A cache is a copy with a clock on it. The failures are the clock, the key, or the moment it expires.

A TTL

Each entry dies at a time you chose. A long one serves the old value. A short one sends every read to the database.

A stampede

A popular key expires, and every request rebuilds it in the same second.

A negative result

Caching the absence of a row saves a lookup, until the row exists and the cache still says it does not.

Invalidation

The write removes or replaces the entry. A cache that only expires will serve the previous value until the TTL.

The cache key

The key includes every input that changes the value. Leave one out, and two callers share an answer.

45

Beside one response

Some work does not fit a request that ends before the next one starts.

A WebSocket

A connection that stays open. Either side can send.

Server-sent events

The server streams text down one response. The browser reconnects when the stream drops.

A range

The client asks for a slice of a file. A download can resume, and a video can seek.

MQTT

A small publish-and-subscribe protocol, built for devices that wake, send, and sleep.

46

A stronger check

A password is one fact. The account stays yours after that fact leaks when something else must also be true.

A second factor

A code or a device, asked for beside the password.

A passkey

A key pair on the device. The site stores the public half. The private half stays put.

Single sign-on

One login at the identity provider. The applications accept its assertion.

A service account

An identity for a machine, with its own credential and a narrow permission.

Rotating a key

The next key is valid before the current one is revoked, so a deploy is never locked out.

47

The certificate

TLS holds when the name on the certificate matches the URL, and a chain leads to an issuer the client already trusts.

A chain

Your certificate, then the issuer, then an issuer the device already has.

The name

The certificate lists the hostnames it covers. A different hostname fails the check, key and all.

Expiry

A date after which clients refuse the certificate.

Renew early

Replace it while the current one is still valid. An expired certificate is an outage.

A wrong clock

The client treats a good certificate as not-yet-valid, or already dead, because its own clock is off.

Where TLS ends

A load balancer may decrypt. The hop behind it is a separate connection, with its own protection.

48

On the box

When the chart is not enough, the machine will say what the process is doing.

An inode

The file's record: owner, permissions, size, and where the bytes live. The filename is a pointer to that record.

strace

Every system call the process makes, in the order it made them.

Open files

The paths and sockets the process still holds.

A full disk

Writes fail and logs stop. The application often reports a different error.

A descriptor limit

A process may open only so many files and sockets. Past that, accept and open fail.

/proc

The kernel's view of one process, exposed as files you can read.

49

What Git stores

The commands are a surface. Under them, Git is a database of snapshots and names that point at them.

An object

A blob, a tree, or a commit, named by the hash of what is inside.

A snapshot

A commit points at a whole tree. History is the chain of those trees.

A ref

A branch is a name aimed at one commit. Moving the branch moves the name.

The reflog

The local record of where that name used to point. A commit that seems gone is often still there.

Bisect

Mark a good commit and a bad one. Git steps through the commits between them until the break is found.

Rebase

Your commits are replayed onto a new base. The changes stay yours. The hashes are new.

50

From style to pixels

The browser builds a frame in stages. A slow page is usually stuck in one of them.

Style

Which rules apply to which elements.

Layout

Where each box sits, and how tall it is.

Paint

The pixels those boxes are made of.

Composite

Layers put together for the screen. A transform can stay in this stage and skip layout.

A forced layout

Reading a size or a position from script makes the browser finish layout immediately, in the middle of the loop.

51

The language itself

The framework sits on a few rules of JavaScript. The surprising bugs sit on those rules.

A closure

A function keeps the variables of the scope where it was created.

The prototype

An object looks up a missing property on another object. That chain is how behavior is shared.

this

The value comes from how the function was called, rather than from where it was written.

Equality

Two values can be equal after coercion, or equal only when their types already match. Pick the one you mean.

Modules

A file with its own scope, and a list of what it hands to other files.

await

The function pauses on a promise and continues when it settles. The rest of the program keeps going.

52

Types that hold

A type is a claim the compiler can check. The holes are the places you told it to stop.

Null

A value standing in for absence. The bug is reading fields on it.

A union

A value that may be one of several shapes. Tell them apart before you read a field that only one shape has.

A generic

A type that takes another type. A list of users and a list of ids are different lists.

A cast

You asserted a type the compiler could not prove. At runtime the value can be something else.

Outside data

JSON, a query string, and a row arrive without your types. Turn them into a type at the boundary.

53

A log line

A line is useful when someone else can find this request again and can see what failed.

A correlation id

One id on every line of one request, including the calls that request made.

Fields

A key and a value, so a machine can filter. A paragraph is for a person, and it is hard to search.

A stack

The call chain at the throw. Keep it on the error you record.

The sentence on screen

What the person can do next. The exception text stays in the log.

A level

Error means a person should look. Info is the story of the request. Debug stays on your machine.

54

The format

Two programs agree on the bytes. The agreement needs a name, and it has to survive a new field.

JSON

Text, with objects, arrays, and numbers that have a limit on how exactly they round.

A schema beside it

A written description of the fields, so a producer and a consumer can be checked against the same document.

CSV

Rows of text. A comma inside a field, quotes, and a header someone will reorder.

A columnar file

Values of one column sit together. A sum reads that column and skips the others.

A new field

Add it so an old reader still accepts the message. Renaming or removing it is a later, separate change.

55

Instants and dates

A timestamp is an instant. A calendar date is a local agreement about what day it is.

An instant

A point on the timeline. It is the same point in every country.

Civil time

The year, month, day, and hour people say out loud, in a particular place.

A zone

The rules that turn an instant into civil time. Name the zone. An offset such as +06:00 is the answer for right now.

Daylight saving

A civil day can have 23 hours or 25, and one hour on the clock can happen twice.

A duration

A length of time, rather than a point. Three hours is not a timestamp.

UTC in the row

Store the instant in UTC. Convert to a zone when a person is about to read it.

56

Numbers that surprise

The machine's numbers are finite. Some values have no exact representation, so the result is a nearby one.

Overflow

The integer wraps, saturates, or the language throws. Know which of those your runtime does.

A float

A binary fraction. Adding 0.1 and 0.2 produces a value very near 0.3.

Rounding

Money and quantities need a rule for the leftover fraction: half up, half even, or to the smallest unit.

57

Attacks with names

Each of these has a shape. The name points at a specific fix.

Cross-site scripting

Someone else's text runs as script on your origin.

Cross-site request forgery

A page on another site submits to you, and the browser attaches the user's cookies.

Server-side request forgery

Your server fetches a URL the user chose, and that URL can aim at a host only your server can reach.

An open redirect

A parameter picks the next URL, and someone uses your domain as the lure.

Clickjacking

Another site frames your page and harvests the clicks.

Unsafe deserialization

Rebuilding objects from bytes can run code, when the format allows more than data. Prefer a format that carries data alone.

58

SQL for the day

The statements of an ordinary week, and the clauses that keep them honest.

A join

Rows from two tables, matched on a key. A missing match multiplies the two sides.

A common table expression

A named subquery, so the statement can be read from the top.

An upsert

Insert the row, and when the key is already there, update it. One statement, so two requests cannot both insert.

The row, locked

A select that locks the row until the transaction ends. The next writer waits.

A partial index

An index over only the rows that match a condition. The unpaid invoices, rather than every invoice ever stored.

A constraint

A rule the database itself enforces: unique, not null, a foreign key, a check. The database still holds the rule when the application has a bug.

59

A wall around it

One sick dependency should stay inside its own budget.

A circuit breaker

After enough failures, stop calling for a while. Try a single probe later.

A bulkhead

A separate pool of threads or connections, so one endpoint cannot spend the pool.

Shedding

Past capacity, refuse new work with a clear status. Slow answers for everyone are answers for no one.

A deadline

A time by which the call, including every call it makes, has to be finished.

One budget

Each hop spends some of that deadline. The last hop sees the time remaining.

60

How memory comes back

Objects live while something still points at them. A collector reclaims the rest, and the pause is part of the latency.

Mark and sweep

The collector finds every object still reachable from the roots, then reclaims what it did not mark.

A generation

Most objects die young, so the collector looks through the young space far more often.

A pause

The program stops while collection runs. A long pause shows up as a spike.

A live reference

A cache, a listener, or a global is enough to keep an object. The collector will not take it.

The stack

The local variables of the calls that are running. They go away when the call returns.

The heap

Objects that outlive the call that made them. Collection happens here.

61

Bytes on purpose

Text, URLs, and binary each have a way of being written down. Cutting the bytes in the wrong place corrupts the value.

UTF-8

A character may be one byte or several. A slice through the middle of a character is not a character.

Percent-encoding

A reserved character in a URL is written as a percent sign and two hex digits.

Base64

Binary written in a small alphabet, so it can travel inside text. The result is longer than the bytes.

Endianness

The order of the bytes in a multi-byte number. Both sides have to use the same order.

A length prefix

A count of the bytes that follow, so the reader knows where the value ends.

Hex

One byte as two digits. Hashes, colors, and dumps are written this way.

62

The verb

The method is a promise about what the call does when it is sent a second time.

GET

Fetch a representation. Caches and browsers are allowed to repeat it.

POST

Hand the server input to process. Sending it twice can create two results.

PUT

Send the full desired state of one resource. Sending it twice leaves that same state.

PATCH

Send a description of the change. The server applies that description to the resource.

Safe methods

GET and HEAD are defined as reads. Repeating them leaves the resource as it was.

HEAD

The headers a GET would return, with an empty body.

63

Conditional HTTP

The client and the server compare a fingerprint, and skip the body or the write when nothing changed.

An ETag

A fingerprint of one representation.

If-None-Match

Send the body only when the fingerprint has changed. Otherwise the answer is 304.

If-Match

Apply the write only while the fingerprint is still the one the client read.

A validator

The ETag, or a modification time, that a cache compares with the server.

304

The body is unchanged. The client keeps the copy it already has.

64

The image

A picture has a format, a size on the page, and a moment when it is allowed to download.

A format

A photo wants a photographic codec. A diagram with hard edges wants one that stays sharp. A drawing may be a vector.

Width and height

Reserve the box, so the page stays still when the file arrives.

srcset

Several files of the same picture. The browser picks one for the screen it has.

Lazy

A picture below the fold waits until the reader is near it.

SVG

The shapes themselves, so the picture stays sharp when it scales.

65

Without a mouse

A page is finished when it can be used from the keyboard, and named out loud.

Focus order

Tab walks the controls in an order a person can predict.

An accessible name

The text a screen reader speaks for a control. An icon still needs that text.

Contrast

Text and the background behind it are far enough apart to read.

The keyboard

Every action a pointer can take also has a path from the keyboard.

A live region

A message that appears later is announced, and focus stays where it was.

Reduced motion

When the person has asked for less motion, animation stays quiet.

66

More than one language

The sentences, the numbers, and the direction of the page follow a locale.

A locale

A language and a region. Sorting, dates, and numbers follow it.

Plurals

The count picks the sentence. Languages do not split one and many in one shared way.

Direction

Some languages run from the right. Layout follows the language of the page.

A formatted number

The grouping mark and the decimal mark belong to the locale.

A hole in the string

The translation contains the place where the name goes. The sentence is not assembled by gluing pieces in code.

67

A ledger

Money moves as entries. The balance is what the entries add up to.

A debit and a credit

Every movement is two entries, and they sum to zero.

A derived balance

The balance is the sum of the entries. Editing the balance in place skips the history.

A refund

A new entry that reverses a charge. The original entry stays on the books.

A dispute

The money is in question until the case ends. The ledger records that the case is open.

Reconciliation

Your entries and the provider's report are checked until they describe the same movements.

68

The queue, closely

Taking a message, finishing it, and falling behind are three separate events.

A visibility timeout

Once a worker takes a message, the others cannot see it until the timer runs out.

An ack

The worker reports the work finished, and the message leaves the queue.

A delay

The message stays hidden until the time you set.

A retry count

Each failure adds one. Past the limit, the message leaves for the dead letter.

Consumer lag

How far this reader sits behind the newest message.

69

Isolation by name

The level is the contract for what one transaction is allowed to observe of the others.

Read committed

A statement sees only rows that have been committed.

Repeatable read

The transaction keeps the snapshot it started with.

Serializable

The outcome matches some order of running the transactions one by one.

A phantom

A later read in the same transaction sees rows the earlier read missed.

A lost update

Two transactions read a value and both write it back. One of the writes is gone.

A version column

The update carries the version you read. A mismatch means another writer arrived first.

70

The other indexes

A B-tree on one column is the usual one. These are the ones you reach for when the query has a different shape.

A covering index

The index contains every column the query needs, so the heap is left alone.

An expression

The index is on a computation, such as the lowercased email.

GIN

An index for a value that holds many elements: the words in a document, or the keys in a JSON value.

BRIN

A short summary of a table that is already ordered on disk. Small, and enough for large ranges.

One you can drop

An index no query uses still has to be updated on every write.

71

Keys and history

How a row is named, and how you remember that it changed.

A surrogate

A key the database minted. It means nothing outside the row.

A natural key

A key the world already had, such as an email, carrying that world's duplicates and changes.

A soft delete

A timestamp says the row is gone. Every query has to remember to skip those rows.

An audit row

Another table records who changed what. The main row stays the current one.

A UUID

An identifier the client can create, so two sides insert without asking for the next number.

72

The ORM

The library is a convenience. The database still runs a statement.

The SQL it wrote

Log the statement. That text is what ran, whatever the method was named.

A lazy relation

Reading a field sends another query. Inside a loop, that is one query per row.

The identity map

The same row, loaded twice inside one unit of work, is one object.

A unit of work

Changed objects are written together when the unit commits.

SQL beside it

A report, a lock, or a batch is often clearer as a statement you wrote yourself.

73

More attacks

A few more shapes that show up in reviews and in incident writeups.

Path traversal

A filename from the user contains ../ and the read leaves the directory you chose.

Mass assignment

The client sends fields you never offered, and the binder copies them onto the record.

Prototype pollution

A key named __proto__ in the input changes the object other objects delegate to.

ReDoS

One carefully built string makes a regular expression backtrack until a CPU is busy.

XXE

An XML parser fetches an entity the document names, and that entity can be a local file.

A timing leak

The function returns sooner when the first bytes of the secret differ. The duration is information.

74

Headers that lock it down

A few response headers decide what the browser is willing to do with your origin.

HSTS

The browser remembers to use HTTPS for this host, for as long as you asked.

Subresource integrity

A hash on a script or a stylesheet. The browser refuses the file when the hash does not match.

HttpOnly

Script running on the page cannot read this cookie.

SameSite

The cookie is withheld when another site is the one submitting the request.

A nonce

A one-time value in the content security policy and on the script tag. Only a script carrying it may run.

75

OAuth, piece by piece

The login at another provider is a handful of values. Each one prevents a specific mix-up.

The authorization code

A short-lived code the browser carries back. The server trades it for tokens, where a secret can stay.

A redirect URI

The exact address the provider may send the person back to.

The state parameter

A value you created, and check on return, so this response belongs to the request you started.

A scope

The list of permissions the person is asked to grant.

A refresh token

A longer-lived secret that mints the next access token. It is stored as a secret.

PKCE

Proof that the client exchanging the code is the same one that started the login.

76

A sketch of the load

Before the diagram, four numbers. They tell you which box runs out first.

Queries per second

The reads plus the writes you must serve at the peak you care about.

The read ratio

How many reads arrive for each write. It decides whether a cache or a replica changes the shape.

Bytes stored per day

The size of one record, times how many you keep, times how many days you keep them.

The bottleneck

The first thing that fills up: CPU, connections, a lock, or the disk.

77

Tests of another shape

One example is a start. These checks cover inputs you did not sit down and type.

A table of cases

One body, and a list of inputs beside the output each one should produce.

A property

A statement that has to hold for any input a generator builds.

A contract

The consumer records the shape it depends on. The provider's build fails when that shape drifts.

A clock you set

The test chooses the time. The code accepts that clock as an argument.

78

The pipeline

The build is a product. It installs the same versions, and it goes red for a reason you can see.

A lockfile

The exact versions that were installed. The next install resolves to those versions.

A required check

The branch stays unmerged while this job is red.

A matrix

The same job, once for each version or system you claim to support.

A cached dependency

Packages from the last run, restored while the lockfile is unchanged.

Lint that fails the build

Style and static checks turn the job red. A comment in the log is easy to miss.
